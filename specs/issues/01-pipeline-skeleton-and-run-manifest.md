# 01 — 流水线编排骨架与运行清单

**What to build:** 一条可命令行触发的串行流水线：按 collector → analyzer → organizer 顺序执行，整个执行过程通过一份「运行清单」文件追踪进度。清单记录当前日期每次运行中每个阶段的开始/完成/失败状态、处理条目数与错误明细。阶段失败即中断整条流水线（fail-fast），下一次重跑时自动跳过已完成阶段（幂等重跑）。流水线入口对日期参数幂等，同一天多次运行不会重复处理已完成阶段。第一阶段用桩实现来验证骨架闭环：真实阶段（02–04）落成后无缝替换。

- 数据在 Agent 间以文件契约传递（raw/ 原始文件、articles/ 已分析文件），本票先定义并校验这两类文件的 JSON schema 契约。
- 本票同时落实编排语义决策：进度追踪（运行清单）、文件契约（schema）、重跑策略（幂等跳过）、上游失败（阶段失败即中止，单条失败记录并跳过）。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 命令行入口可按指定日期启动串行流水线，三个阶段按序执行
- [ ] 运行清单文件正确记录每个阶段的 status、时间戳、条目数与错误明细
- [ ] 某阶段失败时流水线立即中止，且运行清单标记为失败
- [ ] 对同一天重跑，已完成阶段被跳过，不重复执行
- [ ] raw/ 与 articles/ 的 JSON 文件契约 schema 已定义并有校验函数
- [ ] 桩阶段替换为真实阶段后骨架无需改动（验收在 02–04 落地后复验）
