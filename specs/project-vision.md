# AI知识库 · 项目愿景 v1.0

## 要做什么

面向个人开发者的 AI 前沿情报自动采集与知识沉淀系统。每日从三个公开信源抓取 AI/LLM/Agent 相关内容，由多 Agent 流水线完成**采集 → 分析 → 整理 → 发布**，沉淀为**可检索的本地结构化知识库**。

### 1. 信源采集（三源全上）

| 信源 | 采集口径 | 数量 |
|------|----------|------|
| GitHub Trending | 直接过滤，仅保留 AI/LLM/Agent 相关项目 | 10 条/天 |
| Hacker News | 只看 AI 标签相关帖子 | 单源上限在实现计划中确定 |
| arXiv | 关键词匹配过滤 | 单源上限在实现计划中确定 |

- 约束：三源合计**有效知识条目 ≥ 10 条/天**（这是硬性下限，不因单源零产出而下降）。
- 采集频率：两次采集间隔不低于 30 分钟，遵守目标网站 `robots.txt` 与使用条款。

### 2. Agent 深度分析

对每条入选条目**全部**执行深度分析，不做分层粗筛：

- **摘要**（中文）
- **标签**
- **重要度评分**（1-10）
- **亮点列表**（2-3 个）
- **关联模型**
- **英文摘要**

采集阶段的摘要控制在 200 字以内。

### 3. 知识条目输出

- **格式**：JSON，单条归档。
- **字段**：来源信息（`source`、`source_url`、`fetched_at`）+ 分析输出（中文摘要、标签、评分、亮点列表、关联模型、英文摘要）+ 检索字段（`id`、`created_at`、`status`）。
- **溯源**：每条知识条目**必须**携带原文链接（`source_url`），可检索的前提是可溯源。
- 按日期归档到 `knowledge/articles/`，命名 `{date}-{source}-{slug}.json`。

### 4. 检索与分发

- **检索**：V1 提供本地自然语言检索/查询接口（CLI 或 Web），对历史知识条目可提问。
- **发布**：经 Telegram / 飞书等渠道分发（`status` 为 `published` 的条目）。

## 不做什么

### 彻底不做

- 多用户与账号体系
- 公开运营 / 对外发布产品
- 评论、点赞、社交互动
- 移动端 App（检索与分发走 Telegram / CLI / Web 接口）

### 本期不做但计划

- 爬虫对抗 / 绕过反爬（尊重 robots.txt，遇封锁即跳过）
- 历史数据的自动增量回填（只采上线日起的新数据，不追溯过往）

## 边界&验收（V1）

| 维度 | 指标 |
|------|------|
| 每日产出量 | 三源合计有效知识条目 ≥ **10 条/天** |
| 链路稳定性 | 采集→分析→整理→发布全链路无人工干预成功率 **≥ 90%** |
| 时效性 | 滚动 24h 窗口（**昨 9:00 → 今 9:00**）数据，**当天 9:00 前**完成采集→分析→入库 |
| 检索质量 | V1 建立 **20 条基准问题测试集** + 自动化脚本衡量；**90% 命中率为 v0.2 验收线**（V1 不设硬指标） |

## 怎么验证

- **回归验证**：自动化脚本跑测试集，覆盖采集数量、链路稳定性、时效性三个指标。
- **检索验证**：20 条基准问题 + 自动化脚本，作为 v0.2 的 90% 命中率验收基线；V1 阶段日常使用为辅助观察。
- 验证数据以台账/脚本输出为准，不依赖主观感受。
